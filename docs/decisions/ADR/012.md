# ADR-012: Milestone batching, bounded continuation and two-pass freshness

Status: CURRENT decision, authorized by the senior/user's 2026-09-12 implementation instruction. Team-wide activation occurs when the reviewed R1/#40 commit containing this ADR lands on main. Its presence on a candidate branch is not evidence of merge or production approval.

## Decision

Adopt the [long-running policy](../../plans/LONG-RUNNING-WORK.md). Tasks remain small scoped units. A batch is an explicitly authorized ordered queue; agents continue through its dependency-ready tasks without another prompt or PR per subtask. Commits/checkpoints are recoverable progress; the milestone PR is the human integration/review boundary.

Plan ten remaining MVP milestone review closures, reusing #40 for R1 and #41 for R4 while appropriate. Ten is a delivery budget, never an absolute safety cap. Split an unreviewable milestone or necessary fix and record why. Required checks, independent human review and release approval remain mandatory.

Use isolated short-lived contributor branches/worktrees, frequent declared-commit integration, one integration editor and one draft PR per milestone. Temporary batch/rN-* branches expire at merge; main remains canonical and protected. No permanent develop/qa/uat hierarchy. A declared exact integration SHA is a provisional test baseline, not authority to redefine contracts. Random peer branches are not authoritative.

Before final task/batch handoff perform exactly two fresh upstream observations: inspect/reconcile/test Pass 1, independently fetch/inspect/reconcile/test Pass 2, then stop. Main is always observed; only the declared integration baseline is additionally consumed. The second-pass SHA is the cutoff. Later changes belong to integration/review or a new assignment, never an autonomous Pass 3. Early interrupted handoffs record incomplete verification without claiming freshness.

## Supersedes and preserves

Refines only ADR-007's task-to-branch/review cadence and the interpretation that every small task requires a new prompt/PR. Its three owners, single-editor central files, isolated worktrees and protected-main integration are preserved. Explicitly supersedes old CETECH starter-prompt single-task stop clauses for an approved batch; other constraints remain. The upstream Transfer Kit is not replaced.

ADRs 001–011, commercial ownership, v1.0.0 contracts, pricing/payment/PWA invariants and operation-specific CP-04 gates remain controlling. No product implementation, shared contract change or production write is granted by this workflow decision.

## Rationale and consequences

Reduce repeated human handoffs while retaining early combined testing and recoverable context. Refreshing twice bounds drift correction in an active repository; it does not guarantee perpetual freshness or replace final GitHub checks/review. An unresolved owner/contract conflict blocks the affected task. No agent self-authorizes scope or approval through a manifest edit.

WS1/WS2/WS3 assignment, handoff and integration process only. Domain/wire contracts unchanged. WS3 owns governance/CI and serializes central leases. Ben is the requested independent R1 reviewer; reviewer acceptance/approval is separately evidenced.
