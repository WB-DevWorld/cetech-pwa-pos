# ADR-015: Independent return money and stock-disposition wires

Status: CONTRACT REFINEMENT CANDIDATE / AWAITING REQUIRED CONSUMER+PRODUCER REVIEW. Recorded 2026-09-15 under the senior RT-01 contract-freeze assignment on issue #27. This ADR does not grant implementation, merge, live refund, restock, or production approval.

## Problem

Frozen v1 already defined `ReturnPort.preview/execute/resolve` and `PaymentPort.refund`, and the bridge exposed only `POST /returns/preview`. RT-01 cannot execute safe returns while the Decision Register still classified refund bridge execution wire endpoints as UNRESOLVED. Missing pieces were:

- a trusted commerce-order refund/accounting command distinct from tender money;
- a separate physical stock-disposition command;
- independent durable identities, idempotency and GET/resolve paths;
- an explicit historic-economics snapshot so refunds cannot use today's prices;
- aggregate `ReturnResolution.completed` that cannot hide a pending required money or stock effect;
- conservative handling of `opened_resellable` / `defective` instead of a guessed restock policy.

## Decision

Keep v1.0.0 as the sole domain schema. Refine it in place; do not invent a parallel temporary shape or rename unrelated contracts.

1. **Separate effect ownership**
   - Return intake and approval: `ReturnPort` (POS use-case). Browser execute remains intent-only (`returnId` + server fingerprint + optional `approvalId`).
   - Tender money: `PaymentPort.refund` with `RefundChannel` `provider_electronic` | `cash_ledger`. Amount is server-copied from historic snapshot. Provider names stay in adapters.
   - Commerce-order refund/accounting: server-only `BridgeReturnEffectsPort.applyCommercialRefund` / `resolveCommercialRefund`.
   - Physical stock: server-only `BridgeReturnEffectsPort.applyStockDisposition` / `resolveStockDisposition`.
   - Cash register UX and cash payout implementation remain later RT-01 / FE-06. `CashMovement.kind = cash_refund` already exists for the later ledger write.

2. **Historic economics**
   - `HistoricSaleEconomicsSnapshot` is server-owned. Preview, refund and stock commands bind `economicsVersion`.
   - Never refund from current catalog or current provider pricing. Original line subtotal/discount/tax/total and original tender control.
   - Cumulative returned quantity ≤ original sold quantity. Remaining refundable money ≤ original tender.

3. **Independent idempotency**
   - Distinct durable IDs: `refundId`, `commercialRefundId`, `stockDispositionId`.
   - Distinct journal operations: `return.execute`, `return.resolve`, `payment.refund`, `refund.resolve` (preserved), `bridge.commercial_refund`, `bridge.stock_disposition`.
   - Distinct command `Idempotency-Key`s. Money completion with stock pending, or stock completion with money `requires_attention`, must not duplicate the successful side.
   - Same key + same canonical request hash replays. Same key + changed economics/body → `IDEMPOTENCY_CONFLICT`. Timeout → resolve, never treat as failure-before-effect, never open a new key.

4. **Ambiguity recovery**
   - Effectful POSTs may return 202 `OPERATION_IN_PROGRESS`.
   - GET resolve exists for return aggregate, commercial refund and stock disposition.
   - Unknown status → `nextAction=resolve` or `contact_manager`. Blind retry under a new key is forbidden.

5. **Stock safety**
   - Explicit `StockDisposition`: `restock_sellable` | `no_automatic_restock`. No `refund => restock=true`.
   - `damaged`, `quarantine`, `not_physically_returned` cannot request sellable restock (schema `oneOf` on `StockDispositionCommandLine`).
   - `opened_resellable` and `defective` are `tenant_policy_required`. Until a tenant/manager policy is bound into the preview fingerprint, intended disposition fails closed to `no_automatic_restock`. This ADR does not invent that policy.

6. **Provider neutrality**
   - Shared contracts do not name Paystack, Woo, Stripe or MoMo. Commerce accounting is a provider-neutral commercial-refund effect; the current producer is the Woo bridge.

7. **Approval binding**
   - Server fingerprint covers sale, lines, quantities, conditions, `economicsVersion`, refund total, intended dispositions/policy result and `approvalRequired`.
   - `ReturnApprovalBinding` ties `approvalId` to that fingerprint, actor and return identity. Approval for return A cannot authorize changed return B.

8. **Aggregate completion**
   - `ReturnResolution` always carries `providerRefund`, `cashRefund`, `commercialRefund` and `stockDisposition` summaries.
   - `completed` only if every required effect is `completed` or `not_required`. `no_automatic_restock` is `not_required` and does not block completion.
   - Canonical schema `oneOf` (not prose-only): the `completed` variant requires `SettledIndependentEffectSummary` on all four effects, so `completed` plus `pending` / `requires_attention` / `not_started` / `not_found` fails validation.
   - Existing `refund_pending` remains for money-outstanding cases; `in_progress` covers mixed pending (including stock-only pending).

9. **Cross-owner implementation boundary**
   - WS3 owns this contract candidate.
   - WS1 (`@Ben-001-sys`) must consumer-review POS ReturnPort / preview / execute / resolution.
   - WS2 (`@Emmanuel-coder-prog`) must producer-review bridge commercial-refund and stock-disposition routes.
   - WordPress plugin implementation is WS2 after acceptance. Dependent POS/Supabase return engine is later RT-01 after acceptance. This ADR does not authorize those implementations.

10. **Backward compatibility**
    - Quote, prepare, cash, electronic payment, finalize, cancel and receipt contracts are unchanged.
    - Coordinated preproduction freeze: additive required fields on return/refund types; closed schemas still reject extras. Version remains 1.0.0. Not an installed-PWA production change.

## Rationale

RT-01 acceptance requires one refund effect and an independent stock effect, quantity caps, no auto-restock for damaged/quarantine/non-returned goods, and resolve-not-retry for unknown refunds. Preview-only bridge wiring could not express those invariants.

## Supersedes

Decision Register fact “Refund bridge execution wire endpoints: UNRESOLVED for M2 execution”, replacing it with this contract candidate pending required reviews. Does not supersede ADR-003 structural freeze, ADR-004 tender/sale separation, or ADR-008 historic-vs-current pricing authority.
