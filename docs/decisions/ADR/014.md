# ADR-014: Ownership-preserving milestone execution

Status: CURRENT human direction, explicitly authorized by the senior/user on 2026-09-13; repository adoption is pending independent review and merge of this correction. This instruction narrows implementation authority immediately for the assigned correction. A candidate ADR does not prove merge, approval or production readiness.

## Decision

Task ownership survives batching. An agent may automatically implement the next ready authorized task only when both its human owner and workstream match that task's declared owner, with applicable path permissions and central leases. At a cross-owner transition, stop implementation, publish the tested dependency and hand off to the named owner. An integration queue describes assembly order; it is not the integrator's implementation queue.

WS3 may coordinate, review, import declared tested commits, run combined checks, and implement separately authorized WS3 glue/tasks. It may not implement WS1/WS2 behavior merely because those tasks are ready, their owner is unavailable, or their paths appear in a milestone lease. Review fixes normally return to the task's human owner. Explicit senior reassignment must record old/new human/workstream, task, paths, authority, reason and expiry in CURRENT-WORK before work starts; a planning tool or agent cannot grant it.

Cross-owner dependencies use exact tested provisional integration SHAs, without an intermediate main merge. Record task owner, implementing human, source branch/SHA, imported SHA, tested combined SHA, next owner and acceptance limits. PROVISIONAL_TEST and INTEGRATED_AND_TESTED do not mean merged, live accepted or permitted to cause remote effects. Integrate/test throughout the milestone, not only at its end.

For R5 onward, use one neutral WS3-owned batch/rN-* integration branch and milestone PR. Contributors retain isolated ws1/**, ws2/** and ws3/** branches. R4/#41 is an explicit existing-branch exception; preserve its history and finish its current independent review process. Do not retroactively infer implementation permission from its combined path list.

GitHub PR authors cannot approve their own PRs. A neutral branch improves review routing but cannot make an implementer's review of their own contribution independent. Record review coverage by task/owner/final SHA; use the existing three humans for cross-review rather than inventing a fourth developer.
