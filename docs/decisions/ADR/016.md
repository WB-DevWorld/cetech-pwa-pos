# ADR-016: Immutable receipt product-name and SKU snapshot

Status: CURRENT for this WS3 foundation. Recorded 2026-09-18 under explicit senior authorization for POS receipt product-name presentation. Not production approval. Not WS1 compact-UI work.

## Problem

`ReceiptLine.name` was populated from `QuoteLine.productId` and `variationLabel` from `variationId`. That stored provider-neutral IDs in presentation fields, so receipts could not show sale-time product names or SKUs. Compact POS wrapping is a separate WS1 concern and must not truncate catalog, search, or commerce names.

## Decision

Keep v1.0.0 as the sole domain schema. Additive optional fields only; do not change Quote pricing authority.

1. **Sale-time capture vs receipt freeze.** At prepare, join the POS catalog projection onto the quote lines and persist the **full** sale-time name, variation label, and effective SKU onto the sale. Do not shorten names or apply `showSku` at prepare. At finalize, load current receipt settings, compute receipt-only `displayName` via `formatReceiptDisplayName`, apply `showSku`, and persist the immutable `ReceiptSnapshot`. Reprint reads that stored snapshot only. No Woo/network lookup at print or reprint.
2. **`ReceiptLine` fields.**
   - `name`: full sale-time product name (never a product/variation id).
   - `displayName?`: frozen printable name. New receipts always write it. Absent on historic snapshots; those remain valid.
   - `sku?`: frozen effective SKU. Omit when missing or when `showSku` was false at snapshot time.
   - `variationLabel?`: sale-time variation label, not a variation id.
3. **Display-name rule.** `formatReceiptDisplayName(fullName, settings)` runs only when the receipt snapshot is generated (`freezeReceiptLine` at finalize). If shortening is disabled, `displayName = fullName`. If enabled and the name exceeds `productNameMaxCharacters`, shorten and append one Unicode ellipsis (`…`) so the result including the ellipsis does not exceed the maximum. Never mutate `fullName`, `CatalogItem.name`, search text, cart identity, sale presentation lines, or provider payloads.
4. **SKU rule.** At prepare, capture variation SKU if non-empty; else parent SKU; simple products use their own SKU; omit when none exists. At receipt freeze, omit the field whenever `showSku` is false.
5. **Operational settings.** POS-owned `ReceiptSettings` and `pos_receipt_settings` (organization+location). Defaults: `shortenProductNames=false`, `productNameMaxCharacters=40` (bounds 1–256), `showSku=false`. Missing rows mean those defaults. Not Woo commerce truth. Changing settings after completion cannot alter a historic reprint.
6. **Fail closed.** If sale-time catalog presentation is unavailable at prepare, do not persist `productId` as `name`.

## Rationale

Quote remains pricing authority. Catalog projection is the existing provider-neutral presentation boundary. Receipt immutability already required a sale-time snapshot; this fills the missing presentation data without a second catalog master.

## Supersedes

The prepare-time mapping `ReceiptLine.name <- QuoteLine.productId` / `variationLabel <- variationId`. Does not supersede ADR-003 structural freeze, ADR-004 receipt/print separation, or ADR-008 pricing authority.

## Consequences

- WS3 implements contract, prepare snapshot, settings persistence, and tests.
- WS1 (`@Ben-001-sys`) later renders `displayName ?? name` and optional `sku` on receipt paper. Compact two-line POS display is a separate frontend task and must not reuse the receipt shortener against catalog data.
- WS2 quote/bridge wires are unchanged.
- Version remains **v1.0.0**. Historic receipts without `displayName`/`sku` still validate.

## Affected contracts

`ReceiptLine`, `ReceiptSettings`. Quote/Prepare/Payment unchanged.

## Affected workstreams

WS3 owns schema, prepare snapshot, and settings. WS1 consumes receipt JSON later. WS2 unchanged.

## pos-architecture-guardian

Result: **PASS** with WARNING.

- Affected domains: operational receipt snapshot; POS configuration.
- Canonical owners: WS3 contracts/core/server/supabase.
- Current provider: Woo catalog projected into `pos_catalog_items`; not queried at reprint.
- Future providers: same provider-neutral catalog presentation + receipt settings.
- Contracts affected: additive optional `ReceiptLine.displayName`/`sku`; new `ReceiptSettings`.
- Duplicate truth: none; settings are POS operational, names are sale-time copies of the catalog projection.
- Provider leakage: IDs must not occupy presentation fields.
- WARNING: WS1 consumer review is required before UI shortening/SKU rendering. This ADR does not grant production or merge.
