# ADR-013: Provider-neutral cart-level commercial discounts in Quote v1

Status: CURRENT for this R3 continuation; review/merge still required. Approval basis: senior authorization 2026-09-13 to resolve @Ben-001-sys `CHANGES_REQUESTED` on PR #44 (`99dc34fdda4551093ff46a7935b06639371f9cdd`). Not production approval.

## Decision

Keep frozen Quote v1 **structure**. Do not add a fee field, provider-specific discount field, or a parallel wire shape.

A provider cart-level commercial discount may be normalized into existing `Quote.discount` / `QuoteLine.discount` only when the adapter can prove, from authoritative runtime amounts, that the amount is a commercial discount compatible with v1 money identity:

- `quote.total = quote.subtotal - quote.discount + quote.tax`
- `sum(line.discount) = quote.discount`
- for every line, `line.total = line.subtotal - line.discount + line.tax`

For the current Woo transitional provider, a **negative cart-level fee** may be treated as that discount only when **all** of the following hold:

1. Isolated POS quotes still refuse shipping and **positive** fees (v1 has no shipping/fee fields).
2. Every inspected Woo fee has a non-positive amount, and the sum of fee amounts equals `WC_Cart::get_fee_total()`.
3. No fee carries a nonzero tax amount (taxed/ambiguous fees fail closed).
4. Woo cart identity holds in integer minor units: `get_total() = get_subtotal() - get_discount_total() + get_total_tax() + get_fee_total()`.
5. The absolute fee total does not exceed the sum of eligible pre-cart-discount line bases.

If any condition fails, the quote fails closed (`INTEGRATION_UNAVAILABLE`). Adapters must not guess, drop, or invent a fee remainder.

### Allocation rule (deterministic, integer-only)

The allocation base for each line is the authoritative **pre-cart-discount remaining goods amount**: Woo `line_total` (after line-level coupons/line discounts, before cart-level fees). That is the line’s contribution to the cart contents total that a cart-level commercial discount sits beside. Adapters must not copy WoodMart or B2BKing percentage formulas.

Let `D` be the cart-level discount in minor units and `b_i` the base for line `i`. Let `B = sum(b_i)`. Eligible lines have `b_i > 0`. If `D > B` or `B = 0` while `D > 0`, fail closed.

Using **only integer arithmetic** (no binary floating-point):

1. Floor share: `f_i = floor(D * b_i / B)` = `intdiv(D * b_i, B)`.
2. Remainder: `r_i = (D * b_i) % B`.
3. Leftover minor units: `D - sum(f_i)`.
4. Distribute one leftover minor at a time to the largest `r_i`. Tie-break by **canonical `lineId` ascending** (stable UUID / contract line identity). Cart iteration order must not change the result when `lineId`s are unchanged.

Then `line.discount = existing line-level discount + allocated cart-level share`. Combined discount must not exceed `line.subtotal`.

This allocation is CETECH normalization of a cart-level amount onto v1 line fields. It is not a claim that Woo/B2BKing emitted per-line discounts.

## Rationale

B2BKing cart-total percentage discounts arrive from Woo as negative fees. Quote v1 has no fee field. Silent last-line remainder stuffing hid the semantic gap on single-line carts. Ben required an explicit contract/ADR rule plus multi-line and remainder proof. A schema fee field would be a new v1 shape; this ADR keeps provider-neutral `discount` and fails closed when the fee is not a commercial discount.

## Supersedes

Does not supersede ADR-003 (structural freeze) or ADR-008 (authoritative whole-cart runtime). Refines their interpretation of `Quote.discount` so a proven cart-level commercial discount may occupy that field. Supersedes the undocumented R3 adapter behavior that stuffed leftover minor units onto the last cart-iteration line.

## Consequences

- WS3 records the rule in DOMAIN-CONTRACTS and schema descriptions. Version remains **v1.0.0**; no new required properties.
- WS2 implements inspection + largest-remainder allocation. Tests must cover multi-line carts, remainder, ties, existing line discounts, WoodMart-priced bases, and fail-closed cases.
- Live training evidence must capture Woo line bases and cart totals independently, then show bridge allocation matches this rule with zero unexplained minor-unit difference.
- `pricingParityVerified` stays false until independently approved.
- Future non-Woo providers may map equivalent cart-level commercial discounts the same way; they must not add provider fields.
